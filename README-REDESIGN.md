## Database

`.env` points at a **local MySQL** instance (`koruvilla_blog`) that holds a copy
of the production posts, so the redesign shows real content without touching the
live database.

```
DB_CONNECTION=mysql
DB_HOST=127.0.0.1     ← local MySQL; set to your own host if different
DB_DATABASE=koruvilla_blog
```

Start MySQL locally (e.g. `brew services start mysql`), then create the database
and import the dump, or run `php artisan migrate --seed` to build it from the
migrations and `database/data/real-posts.json`. Sessions/cache use an isolated
cookie name + cache prefix.

> Note: the post data is a snapshot, not a live link. New posts published on
> thekoruville.com will not appear here until the DB is re-synced.

## Motion layer (homepage animations)

`resources/js/kv-motion.js` adds a small, dependency-free motion system in the
spirit of Framer Motion / Aceternity: spring easings, orchestrated stagger,
word-by-word headings, scroll parallax, 3D card tilt,
magnetic buttons, counters, icon draw-in and a reading-progress bar.

It is opt-in per element, so it can be used on any Blade page:

| Attribute | Effect |
|-----------|--------|
| `data-mv` | fade + rise (default); variants: `fade`, `left`, `right`, `scale`, `blur`, `words` |
| `data-mv-delay="320"` | delay in ms for that element |
| `data-mv-word-delay="55"` | per-word delay for `data-mv="words"` |
| `data-mv-group="90"` | staggers the `data-mv` children by 90 ms |
| `data-mv-parallax="40"` | scroll-linked translate (px factor) |
| `data-mv-tilt="4"` | 3D tilt (max degrees) on pointer move |
| `data-mv-magnet="8"` | magnetic hover for buttons |
| `data-mv-count="3.5"` | animated counter; `data-mv-decimals="1"` for decimals |
| `data-mv-count-group` | runs counters inside the element when it enters view |
| `data-mv-draw` | draws SVG strokes inside the element |
| `data-mv-progress` | element that becomes the scroll progress bar |

Hidden states are scoped to `html.mv-js`, which the inline `<head>` snippet adds
(and removes after 3 s if the module never boots), so content stays visible
without JavaScript. Everything is skipped under
`prefers-reduced-motion: reduce`.

## Content images — replaceable slots

Every photo you will swap on the homepage lives in one folder:

```
public/assets/img/slots/
```

Each slot has **two** files — a desktop crop and a mobile crop — and the pixel
size is part of the filename:

| Slot | Desktop file | Mobile file |
|------|--------------|-------------|
| Hero slide 1 | `hero-01-desktop-1920x1080.webp` | `hero-01-mobile-900x1600.webp` |
| Hero slide 2 | `hero-02-desktop-1920x1080.webp` | `hero-02-mobile-900x1600.webp` |
| Hero slide 3 | `hero-03-desktop-1920x1080.webp` | `hero-03-mobile-900x1600.webp` |
| Why this location | `location-desktop-1400x1020.webp` | `location-mobile-900x765.webp` |
| Plot 111 sq.yd | `plot-01-desktop-900x1013.webp` | `plot-01-mobile-760x836.webp` |
| Plot 125 sq.yd | `plot-02-desktop-900x1013.webp` | `plot-02-mobile-760x836.webp` |
| Plot 139 sq.yd | `plot-03-desktop-900x1013.webp` | `plot-03-mobile-760x836.webp` |
| Gallery | `gallery-desktop-1920x820.webp` | `gallery-mobile-900x1125.webp` |

**To replace with real photos:** drop a new file over the old one using the
*same name and the same pixel dimensions*. Nothing else to change — Blade and
CSS already point at these paths.

* **Desktop** is served above `720px`, **mobile** at `720px` and below
  (`<picture><source media="(max-width: 720px)">` in `welcome.blade.php`).
* Images are drawn with `object-fit: cover`, so a photo is cropped to the frame —
  never squeezed or stretched. Matching the listed dimensions avoids surprise crops.
* If you deliberately want a different size, rename the file to match the new
  dimensions (`plot-01-mobile-900x900.webp`) and update that one `<picture>`
  block in `resources/views/welcome.blade.php`.

The current files are **placeholders** generated by
`python3 tools/make-slot-dummies.py` — each one prints its own size so you can
see which slot it is. Re-run that script any time to regenerate them.

Blog imagery is dynamic (comes from the `posts` table), so it is not part of
this folder.
